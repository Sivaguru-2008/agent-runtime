# docs/ops — The Operating Manual

The execution layer for the approved 90-day plan (`docs/gtm/90-day-plan.md`).
**This does not change the plan** — it converts every roadmap item (P0.1–P3.4) into
atomic, time-boxed, artifact-producing tasks. Solo founder. Optimize for speed.

## Start here
1. **`11-week-1-runbook.md`** — the literal first-session, copy-paste ship sequence (P0.1→P0.5). Do this first.
2. **`00-operating-manual.md`** — the task catalog. Every roadmap item with steps,
   hours, dependencies, deliverable, success/failure gates, templates, tools, AI prompts.
3. **`03-founder-dashboard.md`** — open this every morning.
4. **`01-daily-execution-plan.md`** — what to do each day.
5. **`02-weekly-sprint-plan.md`** — 13 sprints + the Friday review ritual.

## Systems (use as the work demands)
- `04-kpi-dashboard.md` — the 8 numbers that decide pivot/persevere.
- `05-interview-tracker.md` — 40 targets → 20 interviews → synthesis.
- `06-design-partner-tracker.md` — 5 activated design partners.
- `07-launch-tracker.md` — launch-day checklist + metrics + objections.
- `08-content-publishing-system.md` — 3 essays + social cadence.
- `09-deployment-checklist.md` — public deploy (P0.2 / EN-1).
- `10-sdk-publishing-checklist.md` — npm publish (P0.3 / EN-2).

## The one rule
No new backend correctness features for 90 days. Every week must produce evidence
of market contact — a conversation, a deploy, a signup, a published artifact.
If a task doesn't end in such an artifact, it's not in this manual.
